# CyberMonitor

Self-hosted server monitoring. One 32MB Go binary with both web UIs embedded, no external database — settings and node state live in JSON files under the data directory, connectivity history in an embedded time-series store. Agents run on the machines you watch and report every second; the server aggregates and pushes to the browser.

## What you get

The public status page (what visitors see): node up/down, CPU/memory/disk usage, network rates, and a connectivity chart per node (TCP/ICMP latency plus loss rate, at 1-hour / 1-day / 1-week ranges). Light and dark themes, Chinese and English, optional custom background image.

The admin console (mounted on a randomly generated path, e.g. `/uGXfuIMrjdzJ`) has nine pages: dashboard, nodes, groups, probes, alerts, settings, AI providers, logs. From there you can:

- group and tag nodes, record expiry dates and renewal cycles
- configure probe targets (TCP ports or ICMP), push them to selected nodes, or let agents carry their own via a startup flag
- send Telegram / Feishu notifications when a node goes offline
- plug in OpenAI or any compatible endpoint for ops prompts
- require GitHub OAuth / OIDC login, Cloudflare Turnstile, and brute-force lockout (5 wrong passwords in 15 minutes locks for 15 minutes)

## Install the server

One command; Linux uses systemd, macOS uses launchd:

```bash
curl -fsSL https://raw.githubusercontent.com/crazy0x70/CyberMonitor/main/scripts/one-click.sh -o /tmp/one-click.sh
sudo bash /tmp/one-click.sh
```

It listens on `:25012`; `http://<ip>:25012` is the public status page. The admin entry, username, and password are generated randomly on first start. With the one-click script the password is generated by the installer and printed at the end of the install terminal output (the service log only says "set, not echoed"); without it (manual binary or Docker), the username and password are printed to the server log once on first start. The admin path lives in `settings.admin_path` inside the data directory's `state.json` (one-click default `/opt/CyberMonitor/data`; systemd service name `cyber-monitor-server`, so logs are in `journalctl -u cyber-monitor-server`). Sign in and change the password first thing. Backing up the data directory backs up everything.

Docker works too:

```bash
mkdir -p ./data
docker run -d -p 25012:25012 -e CM_DATA_DIR=/data -v "$(pwd)/data:/data" \
  --name cyber-monitor-server --restart=always \
  ghcr.io/crazy0x70/cyber-monitor-server:latest
```

Note: this command does not mount the Docker socket, so one-click self-update from the admin panel is unavailable for Docker deployments. To enable it, set `CM_ENABLE_DOCKER_UPDATE=1` and mount `/var/run/docker.sock` — the managed update recreates the container and preserves the node identity automatically. Otherwise pull the new image and recreate the container yourself; when you do, keep the identity: reuse the same `-v` volumes and env (`CM_NODE_ID_FILE`, `/state`), or pass `-e CM_NODE_ID=<node id>` (visible in the admin node drawer). A container recreated without any of these registers as a brand-new node.

## Install an agent

The admin "Nodes" page prints a ready-made command once you fill in the server URL and token. Manually:

#### Linux / macOS

```bash
curl -fsSL https://raw.githubusercontent.com/crazy0x70/CyberMonitor/main/scripts/one-click.sh -o /tmp/one-click.sh
sudo bash /tmp/one-click.sh install-agent --server-url http://<server-ip>:25012 --agent-token <your-token>
```

On macOS, running without `sudo` installs a per-user LaunchAgent (starts at login); with `sudo`, a system LaunchDaemon (starts at boot). Logs go to `/var/log/cybermonitor-agent.log` (root) or `~/Library/Logs/` (user).

#### Windows

```powershell
$script = Join-Path $env:TEMP 'one-click.ps1'
Invoke-WebRequest -UseBasicParsing 'https://raw.githubusercontent.com/crazy0x70/CyberMonitor/main/scripts/one-click.ps1' -OutFile $script
& $script install-agent -ServerUrl 'http://<server-ip>:25012' -AgentToken '<your-token>'
```

## Uninstall

The same scripts handle removal. On Linux/macOS:

```bash
sudo bash /tmp/one-click.sh uninstall-agent     # removes agent binary, service, identity files
sudo bash /tmp/one-click.sh uninstall-server    # add --keep-data to keep the data directory
```

A system-level (sudo) install must be uninstalled with `sudo`; a per-user macOS install without it. On Windows:

```powershell
& $script uninstall-agent
& $script uninstall-server    # -KeepData keeps the data directory
```

Uninstall removes binaries, service registrations, and config/identity files; `--keep-data` / `-KeepData` preserves the data directory (nodes, settings, history).

### What the agent reports

CPU (usage, 1/5/15-minute load, model, core count), memory, per-mount disk, disk I/O rates, network up/down rates and cumulative traffic, process count, uptime. ICMP probes need a raw socket — root or `CAP_NET_RAW` on Linux, and `--cap-add NET_RAW` in containers.

### Local probe targets (optional)

When the admin console pushes no probes to a node, the agent can carry its own via `-net-tests`, comma-separated:

```text
1.1.1.1  tcp:example.com:443  DNS@tcp:1.1.1.1:443
```

With a port it speaks TCP, without it ICMP; the `name@` prefix is optional. IPv6 needs brackets: `icmp:[2001:db8::1]`. Unparsable entries are skipped and logged without affecting the rest.

Caveat: `-net-tests` results show up live but do not enter server-side history — charts and loss statistics only cover probes configured in the admin console.

## Networking and proxies

Agents prefer gRPC and fall back to plain HTTP when the path only speaks HTTP/1.1. An HTTPS URL without a port uses 443 for gRPC; HTTP uses 80. When proxying gRPC, do not rewrite it to `/grpc/` — forward the real service prefix:

```nginx
location /cyber_monitor.agentrpc.AgentService/ {
    grpc_pass grpc://127.0.0.1:25013;
}
```

A node with broken IPv6 routing to a CDN will time out on both HTTP and gRPC. Fix the host routing; as a stopgap, add `--add-host <domain>:<working-ipv4>` so that node reaches the endpoint over IPv4.

## Split deployment and static hosting

- By default one port (25012) serves the status page, the admin console, and agent reporting.
- To separate the admin entry from the public page, set `CM_PUBLIC_LISTEN` and serve the public page on its own port.
- The status page can also go to Cloudflare Pages / Netlify / any static host: upload `internal/server/web/public/`, edit `<meta name="cm-api-base">` in `index.html` to point at your server (the server ships with CORS for the public API).

## Performance and known limits

Measured cost of snapshot aggregation plus JSON encoding (Apple M5 Pro, includes building the snapshot, encoding, hashing): ~54µs / 39KB at 10 nodes, ~535µs / 530KB at 100, ~5.7ms / 12MB at 1000 — once per second, so a thousand nodes costs about 1% of one core. Resource *history* is not persisted (only connectivity probes keep 1H/1D/1W history); the numbers on the status page are current values and do not replay after a restart. That is deliberate — persisting resource history costs I/O and disk space that a tool this size does not want.
